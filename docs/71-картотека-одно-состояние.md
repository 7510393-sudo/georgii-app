## 3. Что будет: одно состояние

```swift
enum Deck {                       // что сейчас на экране в разделе «День»
    case day(Date)                // лист открыт целиком (сегодня или карточка)
    case pulling(Date, to: Side)  // лист тянут за край, под ним видна картотека
    case file(Side)               // картотека: .past или .future; «Сегодня» — полоской у края
    case landing(Card, Step)      // карточка закрывается и садится на место
}
enum Side { case past, future }
enum Step { case flying, waiting, settling, down }   // летит · ждёт ленту · встаёт · села
```

- **Одно поле** `deck` в одном объекте (нынешний `Ribbon`, без `Shell`).
  Всё прочее — *вычисляется* из него: «лист закрыт завесой», «лента
  заморожена», «с какой стороны сегодня», «показывать ли шкалу лет».
  `foldSide`, `farSide`, `hintSide`, `todayEnd`, `fileFrom` заменяет одно
  `Side` внутри состояния.
- **Одно место переходов** — `func go(_ event: Event)`: открыли карточку,
  потянули, отпустили за порогом, отпустили до порога, лента встала,
  ушли на карту, вернулись. Перехода нет в таблице — событие молча
  отбрасывается и пишется в след (`Trace`). Недопустимое сочетание
  записать нельзя.
- **Замеры — в одном месте и с меткой.** Положение ячейки дня приходит с
  номером её появления; замер от прежней ячейки отбрасывается по номеру
  (то, что P913 сделала счётчиком, становится правилом для всех замеров).
- **Посадка без таймеров.** Ступень меняется по событию «лента встала»
  (замер совпал с целью два кадра подряд), а не «через 0,3 с». Один
  предохранитель по времени остаётся — на случай, если лента не встала
  вовсе (тогда карточка садится где есть, без мелькания), и он один.
- **Движение** (P893) не меняется: полёт схемы, полупрозрачность на
  подлёте, плотность карточек у края «Сегодня» (`Afar.shift`) — те же
  числа, переносятся как есть.

### Таблица переходов (то, что разрешено)

| Из | Событие | В |
|---|---|---|
| `day(сегодня)` | тянут вниз / вверх | `pulling(сегодня, .past / .future)` |
| `pulling` | отпустили до порога | `day` (тот же день) |
| `pulling(сегодня, s)` | отпустили за порогом | `file(s)` |
| `pulling(карточка, s)` | порог пройден (толчок) | `landing(карточка, .flying)` |
| `file(s)` | нажали карточку | `day(карточка)` |
| `file(s)` | нажали или потянули «Сегодня» | `day(сегодня)` |
| `file(s)` | прокрутили за «Сегодня» | `file(другая сторона)` |
| `landing(_, .flying)` | лента перестроена на сегодня | `.waiting` |
| `landing(_, .waiting)` | лента встала (или предохранитель) | `.settling` |
| `landing(_, .settling)` | схема долетела | `.down` → `file(s)` |
| любое | ушли на карту / календарь | запоминается; по возврату — то же (`file` остаётся `file`, P907) |

Всё, чего нет в таблице (например, «тянут лист во время посадки»), —
не происходит. Сейчас именно такие случаи дают «хаос» из видео автора.

## 5. Проверки, которые надо добавить (в сборке А)

Нынешние проверки не ловят поломки автора, потому что в симуляторе лента
всегда успевает. Нужна **медленная лента в проверке**: ключ запуска, при
котором замеры ячеек приходят с задержкой 0,3–0,5 с и вразнобой. С ним
повторить четыре случая из видео:

1. прошлое → закрыть карточку → «Сегодня» у своего края, не прилип;
2. будущее → карта → назад → закрыть лист → видно будущее, не прошлое;
3. «Сегодня» вверх → завтра из картотеки → закрыть свайпом;
4. закрыть карточку и тут же потянуть снова.

Пока эти четыре не краснеют на старом коде с медленной лентой — проверка
ничего не стережёт; сначала добиться красного, потом переделывать.
