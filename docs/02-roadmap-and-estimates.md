# Дорожная карта, сроки и трудозатраты

Документ-продолжение к `01-competitive-analysis.md`.
Все оценки — в **человеко-днях** (ч/д) одного опытного мобильного разработчика, 1 день = 6–7 часов продуктивной работы.
Диапазон «от–до» отражает разницу между «всё пошло гладко» и «всплыли обычные проблемы платформ».

---

## 1. Принцип планирования: не «фичи», а вертикальные срезы

Стандартная ошибка проектов такого размера — делать экран за экраном и увидеть работающий продукт только на 9-м месяце. Для вашей ситуации (концепция не проверена на людях, кода нет) это опасно.

Предлагаемая последовательность — **четыре среза**, каждый из которых можно дать в руки живому человеку:

```
Этап 0  Проверка ядра        6–9 недель    один экран, но настоящий
Этап 1  Публичная v1.0       +4–5 месяцев  Android, в сторе, платная
Этап 2  iOS                  +2–3 месяца
Этап 3  Удержание и рост     постоянно     импорт, синк, планшет, ИИ
```

## 3. Сводка по этапам

### Этап 0 — Проверка ядра (6–9 недель)

**Цель:** не релиз, а ответ на вопрос «человек открывает это два дня подряд сам, без напоминания?»

Что входит: фундамент (в упрощённом виде) + вкладки План и Дневник + фото + примитивная лента. Одна платформа — Android. Без календаря, без поиска, без настроек, без биллинга.

| | ч/д |
|---|---:|
| Работа | 40–55 |
| С учётом отладки и правок | **45–65 ≈ 2–3 месяца одного разработчика** |

**Критерий прохождения этапа:** 10–15 живых людей, из них ≥ 5 пишут хотя бы 4 дня из 7 на второй неделе без ваших напоминаний. Если этого нет — проблема в концепции, и хорошо, что вы узнали это за 2 месяца, а не за год.

### Этап 1 — Публичная v1.0 на Android (+4–5 месяцев)

Добавляется: календарь Год/Месяц, лента с поиском, все типы вложений, аудио, уведомления, замок, настройки, онбординг, виджеты, биллинг, магазинные материалы.

| | ч/д |
|---|---:|
| Разработка (сумма модулей 2.1–2.5 минус сделанное на Этапе 0) | 110–150 |
| QA, багфиксы, подготовка релиза (+25 %) | 28–38 |
| **Итого Этап 1** | **≈ 140–190 ч/д ≈ 7–9 месяцев одного разработчика** |

**Суммарно от нуля до публичной v1.0 на Android: 185–255 ч/д ≈ 9–13 месяцев одного full-time разработчика.**

### Этап 2 — Android (+2–3 месяца)

Даже при кроссплатформенном фреймворке заново делаются: файловый пикер и bookmarks, виджеты и Controls, уведомления, биллинг App Store, полировка ощущений клавиатуры и скролла.

| | ч/д |
|---|---:|
| Платформенная часть + полировка | 35–55 |
| Если UI пишется нативно с нуля (SwiftUI) | 70–110 |

### Этап 3 — Удержание (постоянно)

Импорт из конкурентов → корзина/история → синхронизация → карта/шаблоны → планшет.

## 4. Три сценария по команде, срокам и деньгам

Ставки — ориентир по российскому рынку 2026 г. для подрядчика/штатного специалиста с налогами; международный аутсорс будет в 1,5–3 раза дороже.

### Сценарий A — Вы сами разработчик, part-time (20 ч/нед)

|---|---|

## 5. Что реально экономит время и деньги

| Решение | Экономия |
|---|---|
| Отказ от собственной синхронизации в v1 (синхронизирует ОС через папку в iCloud/Google Диске) | **15–25 ч/д** и львиная доля будущих багов и обращений в поддержку |
| Старт только с Android | 35–55 ч/д отложены, плюс решается вопрос монетизации в РФ |
| Отказ от планшета и десктопа в v1 | 40–70 ч/д |
| Убрать экран «Заметки», карту, погоду, шаблоны, импорт из соцсетей | 25–40 ч/д и, главное, ясность интерфейса |
| Убрать свои ИИ-функции | 20–40 ч/д + постоянные расходы на API + юридические риски |
| Сокращение настроек с 35 параметров до 12 в v1 | 6–9 ч/д |
| **Суммарная экономия** | **≈ 140–240 ч/д — это 7–12 месяцев работы одного человека** |

Именно поэтому раздел «что лишнее» в анализе — не придирки, а половина вашего бюджета.

## 6. Приоритезация v1.0 (MoSCoW)

**Must have** — без этого продукта нет
- Экран «Сегодня» с вкладками План и Дневник
- Хранение в открытых файлах в папке, выбранной пользователем
- Автоматическое датирование записей и вложений
- Фото и аудио во вложениях
- Курсор на пустой строке + клавиатура при открытии
- Календарь (Месяц) и Лента с поиском
- Замок приложения
- Связка «запланировано / выполнено»

**Should have** — сильно желательно к релизу
- Календарь (Год), виджет быстрого ввода, уведомления о делах, цвета дней недели, тёмная тема, голосовой ввод, экспорт архивом

**Could have** — если останется время
- Календарь (Неделя), фильтры вложений, шрифты и размеры, шаблоны

**Won't have (в v1)** — сознательно отложено
- Своя облачная синхронизация, карта, погода, импорт из соцсетей и фитнеса, ИИ-анализ, планшет и десктоп, экран «Заметки», архивация медиа

## 7. Контрольные точки — чем мерить, а не «ощущать»

| Точка | Метрика | Порог, ниже которого не идти дальше |
|---|---|---|
| Конец Этапа 0 | Доля тестировщиков, пишущих ≥ 4 дней из 7 на 2-й неделе | ≥ 40 % |
| Конец Этапа 0 | Пишут ли люди в **обе** вкладки (План и Дневник) | ≥ 50 % пользуются обеими — иначе антитеза не работает и надо менять концепцию |
| Через месяц после релиза | Удержание на 7-й день | ≥ 25 % (для дневников это уже прилично) |
| Через 3 месяца | Конверсия в платную версию | ≥ 3 % |
| Постоянно | Обращений в поддержку про потерю данных | 0. Любой такой случай — стоп-работа |

## 8. Технологический выбор

| Вариант | Плюсы | Минусы | Вывод |
|---|---|---|---|
| **Android нативно (Kotlin + Compose), ядро хранилища вынесено в KMP-модуль** | Лучшее качество ощущений от текста и клавиатуры — а это ваша идеология; ядро потом переиспользуется на iOS | iOS-UI придётся писать заново | **Рекомендую** при старте с Android |
| **Flutter** | Один код на обе платформы, быстрее всего для одного разработчика | Текстовый редактор и работа с IME — самая слабая часть Flutter; виджеты всё равно нативные | Разумный компромисс, если ресурс один и нужны сразу обе платформы |
| **React Native / Expo** | Быстрый старт, много готового | Работа с файловой системой и фоновыми задачами — постоянная борьба | Не рекомендую для файлоцентричного приложения |
| **Нативно обе платформы** | Максимальное качество | Двойная стоимость | Только в сценарии C |

Отдельно: **формат файлов на диске — это ваш настоящий API.** Он должен быть задокументирован и заморожен раньше, чем выбран фреймворк. Фреймворк можно поменять, формат хранения — уже нет.

## 9. Итоговая честная картина

| Вопрос | Ответ |
|---|---|
| Идея жизнеспособна? | Да, и незанятая ниша реально существует |
| Текущее ТЗ можно строить как есть? | Нет. В нём примерно вдвое больше работы, чем нужно для проверки гипотезы |
| Сколько до проверки концепции? | 2–3 месяца и ~1 млн ₽ (или 5–8 месяцев вашего личного времени) |
| Сколько до публичного релиза? | 9–13 месяцев и 5–7 млн ₽ в рекомендуемом сценарии |
| Где выигрыш? | «План против факта» + «файлы важнее приложения» + предсказуемый интерфейс |
| Где проигрыш, если идти в лоб? | В попытке догнать Day One и Diarium по количеству функций — это гонка, которая уже проиграна |
