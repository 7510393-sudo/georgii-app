## Где код (читать первым)

Каждая беседа Claude Code получает **свою** ветку `claude/<имя>` и может
отправлять только в неё; в `main` отправить из беседы иногда не даёт
GitHub (ошибка 403, так было 09.11). Поэтому свежий код бывает не в `main`.

Как найти свежий код в начале беседы:

```bash
git fetch origin
# ветка, где последняя сборка (номер в .github/release-trigger больше всех):
for b in $(git branch -r | grep -v HEAD); do
  echo "$(git show $b:.github/release-trigger 2>/dev/null) $b"
done | sort -n | tail -3
```

Взять ветку с наибольшим номером и продолжать от неё
(`git checkout -B <своя-ветка> origin/<та-ветка>`), а не от `main`.

**Сейчас (10.11): свежий код — в ветке `claude/wonderful-cannon-0uqyo9`** (сборка 261; прежде `claude/clever-franklin-onbijh`). `main` подтянут
к ней, если GitHub пустил (`git push origin HEAD:main`).

В конце беседы: дописать раздел «Сейчас» ниже и строку про ветку выше,
отправить. Если можно — подтянуть `main` (`git push origin HEAD:main`,
последняя отправка с «[skip ci]»).

## Как работали в последней беседе (что помогло)

- Номер сборки отправлять **отдельно**: если в той же отправке последний
  коммит с «[skip ci]», GitHub пропускает и доставку в TestFlight (10.11 так
  вышло со сборкой 260 — запустили доставку вручную, «Run workflow»).

- Видео автора разбирали по кадрам (`ffmpeg` + сдвиг между кадрами на
  numpy): так нашли и потерю каждого пятого кадра, и прыжок на 26 точек.
- Перед «собери» — ждать зелёную «Сборку iOS» именно этой отправки: 09.11
  шесть отправок подряд были красными (ошибки компиляции), и это заметили
  только при сборке.
- «Собери по частям» — временная отправка, где чужие области возвращены к
  прошлой сборке, номер, затем отправка, возвращающая всё, и следующий номер.
